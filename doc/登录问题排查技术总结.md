### 2. 深入分析

#### 2.1 模拟登录请求

使用 curl 模拟登录请求时发现：
- POST 数据在服务器端被清空
- 响应返回 HTML 而非 JSON

#### 2.2 定位问题根源

通过在代码中添加调试日志，追踪到两个关键问题：

**问题一：CSRF 保护机制**

文件位置：`framework/base/router.class.php` 第 261 行

```php
if($this->config->framework->filterCSRF)
{
    $httpType = (isset($_SERVER["HTTPS"]) && $_SERVER["HTTPS"] == 'on') ? 'https' : 'http';
    $httpHost = zget($_SERVER, 'HTTP_HOST', '');
    $apiMode  = $this->app->apiVersion || isset($_GET[$this->config->sessionVar]);
    if(!$apiMode && (empty($httpHost) or !str_starts_with((string) $this->server->http_referer, "$httpType://$httpHost"))) 
        $_FILES = $_POST = array();  // 清空 POST 数据
}
```

**原因分析**：
- 禅道实现了 CSRF（跨站请求伪造）保护
- 当请求的 `Referer` 头与当前主机不匹配时，会清空所有 POST 数据
- curl 请求默认不发送 Referer 头，导致 POST 数据被清空

**解决方案**：
在请求中添加正确的 `Referer` 头：
```bash
curl -H "Referer: http://localhost:8080/" ...
```

**问题二：响应格式问题**

禅道通过 URL 参数 `t` 或 PATH_INFO 后缀确定响应格式：
- `t=json` 参数：`/index.php?m=user&f=login&t=json`
- `.json` 后缀：`/index.php/user/login.json`

即使发送 `X-Requested-With: XMLHttpRequest` 头，`viewType` 仍由 URL 参数决定。

**解决方案**：
在登录 URL 中添加 `t=json` 参数。

### 3. 登录流程分析

#### 3.1 前端登录流程

文件位置：`module/user/js/login.ui.js`

window.safeSubmit = function(e)

#### 3.2 后端验证流程

文件位置：`module/user/model.php`

```php
public function identifyUser($account, $password)
{
    $user = $this->dao->select('*')->from(TABLE_USER)
        ->where('deleted')->eq('0')
        ->andWhere('account')->eq($account)
        ->fetch();
    
    if(!$user) return false;

    $passwordLength = strlen($password);

    if($passwordLength == 32)
    {
        // 密码格式：md5(md5(原始密码) + rand)
        $hash = $this->session->rand ? md5($user->password . $this->session->rand) : $user->password;
        if($password == $hash) return $user;
    }
    // ...
}
```

#### 3.3 密码加密机制

禅道使用双重 MD5 加密：

```
最终密码 = MD5(MD5(原始密码) + session随机数)
```

其中：
- `MD5(原始密码)` 存储在数据库 `zt_user.password` 字段
- `session随机数` 通过 `/index.php?m=user&f=refreshRandom` 获取

### 4. 正确的 API 登录方式

#### 4.1 完整登录流程

```bash
# 1. 获取 session cookie 和随机数
curl -c cookie.txt -b cookie.txt "http://localhost:8080/index.php?m=user&f=login"
RAND=$(curl -b cookie.txt -c cookie.txt "http://localhost:8080/index.php?m=user&f=refreshRandom")

# 2. 计算加密密码
# 原始密码 Dabai@123456 的 MD5 是 ab43104e3bc84e6343139053b2c3039b
PASSWORD_HASH="ab43104e3bc84e6343139053b2c3039b"
ENCRYPTED_PASSWORD=$(echo -n "${PASSWORD_HASH}${RAND}" | md5)

# 3. 发送登录请求
curl -b cookie.txt -c cookie.txt -X POST \
    "http://localhost:8080/index.php?m=user&f=login&t=json" \
    -d "account=dev1&password=${ENCRYPTED_PASSWORD}&keepLogin=on&referer=%2F" \
    -H "Content-Type: application/x-www-form-urlencoded" \
    -H "X-Requested-With: XMLHttpRequest" \
    -H "Referer: http://localhost:8080/"
```

#### 4.2 关键请求头

| 请求头 | 值 | 说明 |
|--------|-----|------|
| Referer | http://localhost:8080/ | 必须与当前主机匹配，否则 POST 数据被清空 |
| X-Requested-With | XMLHttpRequest | 标识 AJAX 请求 |
| Content-Type | application/x-www-form-urlencoded | 表单数据格式 |

#### 4.3 关键 URL 参数

| 参数 | 值 | 说明 |
|------|-----|------|
| m | user | 模块名 |
| f | login | 方法名 |
| t | json | 响应格式（必须） |

## 技术要点总结

### 1. CSRF 保护机制

禅道实现了严格的 CSRF 保护：
- 检查 `Referer` 头是否与当前主机匹配
- 不匹配时清空 `$_POST` 和 `$_FILES`
- API 模式下（`apiVersion` 或 session 参数存在）可绕过

### 2. 密码安全机制

双重 MD5 加密 + 随机数：
- 防止重放攻击
- 每次登录密码加密值不同
- 需要先获取 session 随机数

### 3. 响应格式控制

- `viewType` 由 URL 参数决定，与请求头无关
- JSON API 需要显式指定 `t=json` 参数

## 附录：常见问题

### Q1: 为什么 curl 登录失败但浏览器正常？

A: 浏览器会自动：
- 发送正确的 Referer 头
- 执行 JS 获取随机数并加密密码
- 处理 session cookie

### Q2: 如何获取用户密码的 MD5 值？

A: 查询数据库：
```sql
SELECT account, password FROM zt_user WHERE account = 'dev1';
```
或计算：
```bash
echo -n "Dabai@123456" | md5
# 输出: ab43104e3bc84e6343139053b2c3039b
```

### Q3: 如何绕过 CSRF 保护？

A: 两种方式：
1. 添加正确的 `Referer` 头（推荐）
2. 使用 API 模式（添加 `apiVersion` 或 session 参数）
