## 一、项目概述

ProManage 是基于禅道项目管理系统的二次开发项目，目标是为开发人员提供定制化的工作界面，并集成即时通讯（职聊）功能。项目采用 Docker 容器化部署，前端基于禅道 ZIN UI 框架，后端使用 PHP 8.1 + MySQL 8.0。

## 三、当前阻塞问题

### 🔴 问题1：用户登录失败（严重）

**现象：** 所有用户（包括 admin、dev1）均无法通过浏览器登录禅道系统。

**排查过程：**
1. 浏览器 Playwright 测试：点击登录后停留在登录页面，无错误提示
2. curl 测试：POST /login 返回登录页面 HTML（非 JSON 响应）
3. Docker 日志：POST /login 返回 HTTP 200，但响应体为空（AJAX 请求时）
4. PHP 语法检查：`php -l` 对 zen.php 返回 exit code 139（Segmentation Fault）

**已发现的数据问题：**
- `zt_user` 表中 admin 账号 `role` 字段为空（已修复为 'admin'）
- admin 账号不在任何用户组中（`zt_usergroup` 表无记录）
- dev1 等账号密码 hash 值 `ab43104e3bc84e6343139053b2c3039b` = md5('Dabai@123456')，但禅道登录使用 md5(md5(password) + rand) 双重加密
- 部分账号密码已被改为 md5('123456') = `e10adc3949ba59abbe56e057f20f883e`

**根本原因分析：**
禅道登录流程为：
1. 前端先调用 `user/refreshRandom` 获取随机数 rand
2. 前端计算 `password = md5(md5(原始密码) + rand)`
3. POST 提交加密后的密码
4. 后端用数据库中的 md5(原始密码) + rand 验证

数据库中存储的密码是 md5(原始密码) 的结果。如果原始密码被改过但 hash 不匹配，登录就会失败。

**需要确认：** 各账号的原始密码到底是什么？需要用正确的密码重新设置数据库中的 hash 值。

### 🔴 问题2：PHP Segmentation Fault（严重）

**现象：** 容器内 `php -l /apps/zentao/module/user/zen.php` 返回 exit code 139。

**可能原因：**
- PHP 8.1 与 OPCache/JIT 的兼容性问题
- 文件编码或内存问题
- 容器内 PHP 配置问题

**影响：** 修改 user/zen.php 添加 devws 重定向逻辑后，可能导致 PHP 崩溃，从而影响整个登录功能。

### 🟡 问题3：容器文件同步（中等）

**现象：** Docker 容器中 Apache 使用 `/apps/zentao` 目录，但 volume 挂载到 `/app`，两者需要手动同步。

**影响：** 修改本地文件后，需要手动执行 `docker exec zentao-web cp /app/module/xxx /apps/zentao/module/xxx` 才能生效。

### 🟡 问题4：devws 登录重定向未生效（中等）

**现象：** 修改了 `user/zen.php` 添加非admin用户跳转 devws 的逻辑，但因登录功能本身不可用，无法验证。

**代码修改位置：**
- `module/user/zen.php` 第199-209行：login() 方法中添加 devws 重定向
- `module/user/control.php`：login 方法中添加 devws 重定向

**当前状态：** 本地代码已修改但未同步到容器（因 PHP 崩溃问题）。

## 八、关键经验教训

1. **禅道登录加密机制**：密码使用 md5(md5(password) + rand) 双重加密，直接修改数据库密码需了解此机制
2. **容器双目录问题**：Apache 使用 /apps/zentao，volume 挂载到 /app，修改代码后必须同步
3. **PHP OPCache 缓存**：修改 PHP 文件后需重启 Apache 或清除 OPCache
4. **PHP Segfault**：容器内 php -l 可能因 JIT/OPCache 问题崩溃，不代表代码本身有误
5. **ZIN UI 框架**：chatBar 位于 lib/zin/wg/header/v1.php，通过 data-toggle=modal 触发聊天窗口
6. **模块命名冲突**：禅道已有 dev 模块，新建模块需避开已有名称（最终使用 devws）
7. **权限系统**：新模块必须在 zt_grouppriv 表中授权才能被非admin用户访问
